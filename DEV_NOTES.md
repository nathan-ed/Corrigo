## Data storage

Everything about an evaluation is stored in a hidden folder next to its copies:

```
<evaluation folder>/
  01_XXX.pdf, .01_XXX.pdf.yml        copies and their editions (storeEditionsNextToPdf)
  .pdf4teachers/
    comments.yml       comments by exercise (CommentBank): text, exercise, movedTo, hidden, style, copies, pages, fields (copy -> grade path), field
    scoredcomments.yml scored comments catalogs by evaluation signature (now only the "from max" / "from 0" chosen per grade)
    notes.yml          notes (copy stored by file name, relative to the folder)
    notes/*.png        note screenshots
    tags.yml           methods & mistakes: tags (id, exercise it was created for, name, kind, [points, comment, gradePoints, criterion]) + per copy: uses (id, tag, exercise, grade, page, x, y, [labelX, labelY])
    marks.yml          marks scale (kind, min, max, step, table, formula); not written for the Swiss default
```

The hidden folder keeps the name `.pdf4teachers` (renaming it would lose existing data).

- `EvaluationFolders` activates the folder of the opened PDF (`MainScreen.openFile`), saves the previous one first, then loads each registered `Part`. The active folder is set **before** loading (a part may save while loading).
- Writes are atomic (tmp file + move), debounced 1 s, flushed on folder switch and on close (`requestCloseApp`, `UserData.save` on the FX thread only). The data folder is only created when there is something to save.
- `Config(File)` **creates the file**: only use it for files that exist.
- App-wide data (`~/.local/share/Corrigo/`, `%APPDATA%\Corrigo`, `~/Library/Application Support/Corrigo`; copied once from the PDF4Teachers folder at the first start, `PlatformUtils.getDataFolder`): notes taken with no copy open (`teachernotes.yml` + `notes/`), `scoredcomments.yml` (backup and migration source), `evaluations.yml` (evaluation folders opened, for the cross-evaluation search).
- Migrations: app-wide notes move into their evaluation folder when it is opened (all or nothing, old screenshots kept); scored comments catalogs are copied into the folder after the edition is loaded (`ScoredComments.onEditionLoaded`).

- New evaluation (`NewEvaluationWizard`, pure part `NewEvaluationPlan`): scan → students → pages per copy (top of each first page shown) → scale (`GradeScaleSetupDialog`, or ratings from a .yml / another copy's edition written with `GradeCopyGradeScaleDialog.copyToFile`). Never writes over existing copies.
- Exercise pages: no footer controls any more; the page of an exercise is the page of its first leaf grade, unless set in the panel menu (Plus ▾ → Pages des exercices…). `FooterBar.isExerciseCorrectionMode()` = grading tab selected; `areExercisePagesUnknown()` drives the panel banner.
- Hidden tabs: `SideBar.HIDDEN_TABS` (paint, skills), code kept.
- First opening (`Main.firstLaunch`, no settings.yml): `WelcomeWindow` sets the language, then the main window starts and `GuidedTour.start()` runs. The tour is an overlay pane in `MainWindow.tourLayer` (a StackPane over the scene root), not a Popup: popups with transparency show as white frames on X without compositing. The user guide no longer opens by itself.
- Exercise navigation (`FooterBar.selectExercise`, `goToExercise`) applies the exercise directly (`applySelectedExercise`); the hidden footer ComboBox is only kept in sync.
- Digit shortcuts use the typed character (`MathUtils.parseDigitTypedOrNull`): Shift+3 / AltGr+3 typing `#` must not also put the 3rd tag.
- Comment typing performance: suggestions scan the copy once per focus, `CommentBank.Entry` caches its simplified text, the Texts tab list is rebuilt only when that tab is shown, and the Texts tab autocomplete runs only when its own field is focused.

## Key rules and design decisions

- **Grading by lines** (setting `gradingByLines`, on by default; package `corrigo.panel.sidebar.grades.lines`): one text per exercise in the grading panel (`LinesEditor`), a block of lines per sub-question (blank line between them; "b)" at the start of a block chooses the sub-question; an exercise without sub-grades takes all the blocks). `LineGrading` (pure) reads a line (points at the end, signed or not; a number after `=`, `^`, `/`… or a whole number alone after "question", "page", "méthode"… is text, a decimal or "1 pt" is points; a final dot after the points is allowed ("Erreur -1."), not after a number alone ("2."); points typed at the start ("-0.5 Notation") do not count and are shown as a warning; "(…)" is private unless it is points; keywords FULL / ZERO; PNF lines) and grades a block. `LineIds` keeps an id per line across edits (LCS diff: a corrected line keeps its id); the field gives each edit (`TextEdit`, from a `TextFormatter`), so the lines before and after the part edited keep their ids exactly (`LineCorrection.linesOutside`): of two equal lines, the one deleted loses its id and its text, not the other one. The texts of the lines deleted are kept (`LineCorrection.removed`): when an undo of the text (Ctrl+Z in the field) brings their lines back, they are written again where they were (`restoreRemoved`). `LineCorrection` holds, per exercise path, the text, the ids and the grade the lines gave each sub-grade (`computed`): a sub-grade whose value is not its `computed` is typed by hand and never changed by the lines (✎, `resetToLines` with ↺). Grades change only in `setText` (never on load). Saved in the edit file under `corrections` (`Edition.save`; `simpleSave` keeps the section of the file).
- Each line is written on the copy once placed: a click on the free space of a page in the grading tab places the next line (`GradingPanel.isPlacingLines`, a click on an element is for the element), "Next to the grades" or the closing of the copy (`MainScreen.closeFile` → `beforeCopyClosed`, setting `linesAutoPlace`) put the others next to their grade then on the closest free place (`TagScoring.moveToFreeSpotNowOrLater`, scan specks ignored by `FreeSpot.removeSpecks`). The text is a `TextElement` with `correctionLine` = the line id: editing the line edits it, deleting the line deletes it (`reconcile`, no undo step: the text field has its own undo). Ctrl+Z in the field undoes the last click placement first, then the typing; its history starts with the copy.
- PNF lines and the PNF button of the panel write a mark counted for the exercise (`PNFAnnotationManager.addPNFAtGrid(..., topLevelIndex)`); a counted mark has `pnfExercise`, and deleting it removes its bar from the table of the first page (`onCountedMarkDeleted`, `ELEMENT_NO_COUNT_AFTER`: undone with the deletion; `removeMarkFromTable` with `NO_UNDO` when its line is deleted).
- `LineBank` collects the lines of the exercise on the other copies of the folder (`OtherCopies`, read again only when a file changed), and the lines typed with « g » after their points plus the PNF lines of every exercise of every copy, this one included (`collectEverywhere`). Under the text, the lines matching the line being typed (`LineBank.matches`: same sub-question first, then the exercise and the whole test; the caret at the end of its line, no points typed yet): ↑ ↓ choose, Tab or a click takes one, Escape hides them. A warning when the same words have other points elsewhere.
- Typing goes to the text of the exercise from anywhere in the window outside a text field (`GradingPanel.onWindowKey`: a text of the copy selected, the page, a button), never to a shortcut of the old mode. Alt+Enter writes the lines not placed yet next to the grades.
- Typing never sticks to a line: when the field gets the focus (Ctrl+Enter, a click on the copy, Alt+↓ ↑ — handled by the field, which would keep them —, a letter typed on the panel, a click under the last line) or a line is taken, the next letter starts a new line (`LinesEditor.newLineAt`). A click inside the text keeps the caret where it is.
- On the copy, a line "Correct" (all the points) or with points given ("Calculs cohérents +1") is written with a green tick, a line "Faux" (from 0) with a red cross (`LineGrading.CHECK`, `CROSS`, before the words); one click places one line, in the order of the text. Nothing is placed without a click: `linesAutoPlace` is off by default, and Ctrl+Enter / "Next ungraded" with lines not placed shows how many and stays on the copy (the same key again within 5 s goes on). Presentation marks have the size of the comments (`commentsSize`).
- `Config.getBooleanNull` returns null for a missing key: a boolean setting added in a new version keeps its default (it was read as false).
- Selecting a text of the copy while the grading tab is shown keeps the grading tab and gives the keyboard to the text (`TextElement.selectWhileGrading`): Delete / Backspace remove it from the copy (they used to stay in the text of the exercise and remove a character of the lines).

- **Exercise of a comment** (`ExerciseLocator`): comment written for a grade → that exercise; else closest sub-grade above on the same page (2 % tolerance), or first below; else the exercise pages set in the footer bar; else last sub-grade on a previous page; else "General". Only leaf grades count (the totals table is ignored).
- Comment bank entries are keyed by exercise + text with whitespace normalized; comments no longer on any copy are kept (can be hidden via right-click).
- **Math**: `$…$` inline; `$$` with no closing makes the rest math (old texts); `\$` is a dollar; a lone `$` is text; texts with `&&` (old LibreOffice math) keep the old rendering. The "default input mode" setting is hidden and no longer used.
- Mixed text + formulas is rendered as one image (same on screen and in the PDF export), wrapped at the element max width, text in its own font with a per-character fallback.
- Tags: two kinds (METHOD, MISTAKE). A tag is created for an exercise but usable in any: the card and the `#` picker list the tags of the exercise (created for it or used in it) first, then all the others. Names are unique in the evaluation (old per-exercise duplicates are merged when read). A use (occurrence, with an id) is (copy, exercise, tag, grade, placement): the same tag can be on a copy several times, in the same exercise or in several. The name is never written on the copies.
- Placement: the `#` picker stores the spot under the mouse (pill in the left margin at its height, a dot on the spot); chips store `ExerciseTags.getExercisePlacement()` (recognized by `isExerciseSpot`: pill under the grade of the exercise). `#` adds a new occurrence at the mouse, or removes the occurrence pointed at. A dragged pill keeps its own position (labelX/Y); dragging the dot moves the spot. The dot grab area and the pill text keep a minimum size on screen (`TagMarkers.Layer.getPixel`).
- Criteria (`Tag.criterion` = grade path, `EvaluationTags.syncCriteria`, called by `ExerciseTagsCard.update` through `ExerciseTags.syncCriteria`): each leaf sub-grade of the exercise is a METHOD tag, first in the card, not listed in the other exercises, never found by name, not counted in "without method". Its target is its own sub-grade with its total and the comment `ScoredCommentGrades.CHECK` (`$\Large\checkmark$`, rendered alone, centered on the spot). Kept in `tags.yml` (`criterion:`); removed when out of the scale and unused.
- Placed by click (`TagPlacing`, like `RegionCapture`: filter on the main screen, Escape): criteria and methods or mistakes with a comment (`ExerciseTagsCard.isPlacedByClick`), and the PNF chip (always among the mistakes when presentation marks are on). Chip and grading-panel keys arm it; `#`, page keys and the page menu already have a spot.
- Presentation marks (`PNFAnnotationManager`): "PNF" or "PNF : comment" (comments in `UserData.presentationComments`, app-wide, last used first; `buildCommentItems` for the card chip, the page menu and the `#` window). Without exercise selected the mark is written but not counted in the table. The grade of a top-level exercise named like the marks (no sub-grade) is `score(marks on the copy)` (0-1: 2, then −0.5 by mark, at least 0), set with `GradeElement.setAutomaticValue` (not an undo step: undoing a mark recomputes it through `PageRenderer.addElement/removeElement`), on mark changes, and when an empty one is filled once a grade is given on the copy (`onGradingChanged`: typed or by lines), never at the opening. That exercise has no criterion.
- New tag in the card (`buildAdd`) and in the `#` window: one text, its name and its comment (checkbox "write on the copy"); `EvaluationTags.setScoring` renames a tag whose name is its old comment.
- Quick marks (`QuickMarksBar`, above the card): the paint tab shapes (`DefaultFavoriteVectors` LINE, CHECK, CROSS, and the CIRCLE stretched) through `MainScreen.setToPlace`; a click without drag gets `Mark.clickWidth/Height` centered and upright (`setClickedSize`, called by `PageRenderer` on release instead of `defineSizeAuto`, which made them huge). While one waits, the elements of the pages are mouse transparent.
- Mode of an exercise on a copy (`ScoredCommentCatalog.Base`): FULL "by mistakes" or ZERO "by criteria". Automatic: set by the first point placed in the exercise (a negative one: FULL, else ZERO; `ScoredCommentGrades.computeExercise` returns it), kept as `pointsAutoMode` on the grade of the exercise (`KEY_AUTO_MODE`, `GradeElement.get/setPointsAutoMode`) until no point counts. Chosen: for the class, catalog base keyed by the exercise path (older bases by sub-grade still read); for a copy, `pointsMode` (`KEY_MODE`). `getChosenMode`: copy, else sub-grade, else exercise, else null (automatic). Shown and changed in the grading panel header (`GradingPanel.updatePointsMode`, `showModeMenu`; `ScoredComments.setClassMode` recomputes the other copies' edit files, `setCopyMode`).
- Values of the sub-grades of an exercise (`ScoredCommentGrades.computeExercise`, pure, used by `recomputeGrades` for edit files and `ScoredComments.recomputeExercise` for the open copy): with points, `getStart` (0 if its criterion is ticked, else the start kept from a previous version when the mode is not chosen, else the typed value, else max or 0 by mode) plus the points, clamped; by criteria, once the exercise is started (a point or a typed value), an empty sub-grade is a computed 0; a typed value over computed points stays until a point is placed on it.
- Copies graded by previous versions (`keepStoredValues`, on `Edition.load` and before other copies are rewritten): an exercise with computed points and no automatic mode gets FULL, and a sub-grade whose saved value is not the one computed now gets `pointsStart` (`KEY_START`: max, 0 or the typed value that gives it).
- Undo (`TagUndoAction`, registered by `ExerciseTags.addOccurrence`, `removeOccurrence`, `removeAllOccurrences`, `changeOccurrence`, `moveOccurrence`, `restoreOccurrence`, for the open copy only): Ctrl+Z undoes a method or mistake like any annotation. Deleting its element by hand (`onOccurrenceElementDeleted`) registers an `ELEMENT_NO_COUNT_AFTER` action: the element deletion is registered just after it, so undoing puts the element back, then the occurrence.
- A comment written at a spot (`TagScoring.place`, not a tick, not the exercise spot) moves to the free place the closest to its default place (`moveToFreeSpot`: dark pixels of the rendered page and the other elements, grid of 4 px cells grown by one, `FreeSpot.find` within a quarter of the page width); it stays if there is none.
- `FooterBar` toasts have an id: hiding an older one (end of a click placement) no longer removes the message shown just after.
- Points and comment (`TagScoringDialog`, `EvaluationTags.getTargets`): optional points (positive; the kind gives the sign) and comment per tag. Each occurrence counts on its `grade` (the sub-grade whose grade is nearest the spot on the same page, else the active one), or, if the tag has `gradePoints` for that exercise, on each of those sub-grades (comment on the first). A target is written as a `ScoredCommentElement` with id `tag:<tagId>#<useId>[@gradePath]` (`TagEditFiles.elementId`): points only, or "comment (points)", or the comment only with `KEY_NO_POINTS` (not counted). `TagScoring.sync` updates the open copy (JavaFX elements) and the other copies (their edit files, `TagEditFiles.sync`) and recomputes the grades; the grade typed before the first counted element is kept (`KEY_VALUE_BEFORE` / `valueBeforeComments`) and restored when none is left. Deleting such an element by hand removes the occurrence. The old scored comments UI is gone (Grades tab list, panel items, N key, "make it a scored comment"); the engine stays.
- Overview: "This exercise" (tags of the exercise, average points) or "Whole evaluation" (copies having it anywhere, count by exercise).
- Comment suggestions: `CommentBank` remembers the grade field each comment was written for. Ranking: this field, then this exercise, then the others; most used first. Texts typed live and replaced in the same field are forgotten (`updateCopy`), the pending scan is flushed before suggesting.
- Review mode hooks into `FileTab.openNeighborFile`: every previous/next copy shortcut goes through the reviewed copies only.
- Test data and commits must never contain real student names or identifiers.

## Testing

- Unit tests (204): `./gradlew test`. Pure logic has tests: `MathTextTest`, `ExerciseLocatorTest`, `CommentBankTest`, `EvaluationFoldersTest`, `EvaluationTagsTest`, `TagEditFilesTest`, `MarksTest`, `MarkScaleTest`, `NewEvaluationPlanTest`, `MoodleFeedbackTest`…
- GUI tests: never on the real display, data or evaluation folders: only on the fictional class ALPHA, BRAVO, CHARLIE… (skill `corrigo-test`).
  1. `python3 scripts/make_test_eval.py <dir>` builds a fictional evaluation (copies ALPHA…HOTEL in `Classe-A/Test-1`, 2 copies in `Classe-B/Test-1`; exercises with different methods and typical mistakes, grades and a few comments).
  2. `Xvfb :77 -screen 0 1600x1000x24 &`, then `DISPLAY=:77 XDG_DATA_HOME=<tmp>/xdg ./gradlew --init-script <tmp>/isolated-build.gradle run` with the init script setting `allprojects { layout.buildDirectory.set(file("<tmp>/build")) }` (do not rebuild the jar the real app runs from).
  3. In `<tmp>/xdg/Corrigo/settings.yml` set `storeEditionsNextToPdf: true` and `checkUpdates: false`; put the fictional copies in `userdata.yml` → `files.lastFiles` (YAML flow list: edit with python yaml).
  4. Drive with `xdotool`, screenshots with `import -window root`. Mouse wheel and slider drags do not work there: use the scroll bar arrows and keyboard.
  5. Search the log with `grep -a` (it has color codes; plain grep sees a binary file and hides exceptions).
  6. GTK file choosers don't get the keyboard: find the chooser window, `xdotool windowfocus` it, then `ctrl+l`, the path, Return. Dialog windows can fall behind the main window (no window manager): raise them with `xdotool windowraise`.
  7. Never start a window manager or other session-aware program on the test displays: the shell's `SESSION_MANAGER` belongs to the real desktop session. Run the app with `env -u SESSION_MANAGER -u DBUS_SESSION_BUS_ADDRESS … dbus-run-session -- ./gradlew --no-daemon run`.

- **Opening never changes a copy** (to run after any change of the grading): `python3 scripts/make_reopen_cases.py <tmp>/cases` makes fictional copies of every kind of grading (typed, by lines placed or not, typed over the lines, PNF, 1.7 methods and mistakes, 1.6 scored comments, exercise without sub-questions); `python3 scripts/sandbox/reopen_check.py <tmp>/cases/Classe-A/Test-1 --data <tmp>/xdg [--init-script …] [--rounds 3]` opens each copy in the app on a virtual display, saves it, stops it, and compares its edit file: a change of a grade, a line or a text written on the copy fails; positions moved by one grid unit when an old copy is first saved, the version of the file and the mode kept for the old methods and mistakes are only listed. `scripts/sandbox/xdo.py` drives the virtual display (python-xlib; accented letters through a spare key).
- **Anonymous export for a review of the fairness** (grading panel, More menu; `FairnessExport`, pure, tested): one Markdown file with the rule of the points, the grade scale, each copy as « Copie 01 »… (each exercise and sub-question: grade, start, lines, ✎ typed, old scored comments, presentation marks, other texts; the words of the file names of all the copies replaced by [élève] in every copy), then the lines used in the class with the copies that got them, the same words with other points first (⚠). The table copy ↔ number is written next to it, `…-DO-NOT-SEND.csv`.
- **Converting 1.6/1.7 grading to lines**: `java -cp <classes+jars> corrigo.panel.sidebar.grades.lines.LineConversion <folder> <output folder> [PNF name]` reads the edit files (never changed) and writes converted ones: scored comments and grade comments become lines linked to their texts, a grade different from its lines stays typed (✎). Then `reopen_check.py` on the output (blank PDFs of enough pages named like the edit files).
- **Whole evaluations graded in the app**: `python3 scripts/sandbox/full_grading.py <tmp> --data <tmp>/xdg [--init-script …] [--offline] [--seed N] [--only A|B]` grades two fictional evaluations (A: PNF + 5 exercises, sub-questions « a) », « a », « Limites », « 1. Limites », /35, 8 copies; B: exercises without sub-questions, PNF last, 6 copies) exercise by exercise over all the copies (Alt+↓, lines typed during or after the placement, labels in reverse order, private notes, « g », PNF lines, equal lines, Ctrl+Enter), then checks every text, grade (independent model of the rule), written line, mark and the table, and reopens every copy twice (`reopen_check.py`).
- One sandbox app at a time: the app is single instance (`LockManager`), a second one sends its file to the first one even on another display or data folder.
- **Grading by lines, gesture by gesture**: `python3 scripts/sandbox/lines_scenarios.py <tmp> --data <tmp>/xdg [--init-script …] [--offline]` (52 checks: the example of Nathan, two equal lines (both count, one click each, one deleted), a line with « g » taken in another exercise, editing and deleting lines, five clicks five texts, typed grade kept and ↺, cleared grade, reopening, "b)" labels, accents, "Voir question 2", exercise without sub-questions, texts kept by exercise, dragged text, Ctrl+Z after a click, PNF line and table, text deleted on the copy, next copy with lines not placed, grades typed before the lines, setting off). Then `reopen_check.py` on `<tmp>/lines/Classe-A/Test-1`.

## Known issues / not done

- Existing, unrelated: loading skills data logs an `IllegalArgumentException` (empty `NotationType`) on a fresh install; `AutoTipsManager.hideAll()` can throw `ConcurrentModificationException` (not called by the new code).
- Old `&&` comments show their `&&` in the lists (that is how they are stored).
- Previews show the PDF page plus the one comment or tag marker, not the other annotations of the copy.
- The cross-evaluation search only knows folders opened since this storage exists, plus the folders of the files list.
- Tags whose copy was renamed stay attached to the old file name (`EvaluationTags.retainCopies` exists but is not called).
- Mixed text + formula elements cannot be resized with the grab line (their width is the element max width).
- The guided tour highlights empty areas when no copy is open (first opening): it could open the demo class.
- `Compute marks` uses the marks scale of the evaluation open, for every graded copy of the files list (copies of other evaluations listed at the same time get that scale too).
- Formula errors are in English in both languages (`MarkScale.Formula` messages).
- Repo still named `nathan-ed/PDF4Teachers` on GitHub: after renaming it, change `AppLinks.REPOSITORY` and the video links of the guides' READMEs.
